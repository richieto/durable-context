# Security

Use this file only when the initiative has material security, privacy, abuse,
or compliance implications. Omit it when the concern is not applicable or can
be fully dispositioned with a concise reason in the initiative README.

Start from repository evidence and existing accepted decisions. Record no
secret values, credentials, personal data, exploit instructions, or other
sensitive operational material.

## Security Context

Describe the security-relevant change, protected assets, affected actors, and
the trust boundaries or assumptions that matter.

## Authentication And Authorization

Describe identity, session, permission, tenancy, privilege, and audit changes.

## Data Protection And Privacy

Describe sensitive data classification, collection, access, retention,
deletion, encryption, residency, and privacy implications.

## Threats And Abuse Cases

List credible misuse, abuse, privilege escalation, injection, disclosure,
tampering, denial-of-service, or supply-chain scenarios introduced or changed
by the initiative.
